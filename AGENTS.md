# Repository Guidelines

## Project Structure & Module Organization
- `src/` — application code
  - `components/` reusable UI; `pages/` route views (e.g., `auth/`, `dashboard/`, `jobs/`)
  - `contexts/` React providers; `store/` Zustand state; `utils/`, `lib/`, `styles/`, `types/`
- `scripts/` — Node utilities (e.g., `import-jobs.js` reads `scripts/jobs.csv`)
- `dist/` — build output (generated by Vite; do not edit)
- `index.html` — app entry; `supabase/` — backend config; `SOP/` — workflow docs

## Build, Test, and Development Commands
- Install: `npm i` (Node 18+ recommended)
- Dev server: `npm run dev` (Vite with React, hot reload)
- Type check: `npm run typecheck` (TypeScript, no emit)
- Lint: `npm run lint` (ESLint per `eslint.config.js`)
- Build: `npm run build` → `dist/`
- Preview build: `npm run preview`
- Import jobs: `npm run import-jobs` (requires `.env` with `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`, and `scripts/jobs.csv`)

## Coding Style & Naming Conventions
- Language: TypeScript; 2‑space indentation; prefer functional components and hooks
- File naming: components `PascalCase.tsx`; utilities/types `camelCase.ts`/`kebab-case.css`
- Code identifiers: variables/functions `camelCase`; constants `UPPER_SNAKE_CASE`
- React: hooks prefixed `use*`; colocate component styles; avoid default exports for utilities
- Linting: ESLint with TypeScript + React Hooks/Refresh; run `npm run lint` and fix before PRs
- Styling: Tailwind (`tailwind.config.js`); keep class lists readable and deduplicate via small components

## Testing Guidelines
- No formal test suite yet. Recommended: Vitest + React Testing Library
- Naming: `*.test.tsx` colocated with components or under `src/__tests__/`
- Focus: auth flows, routing, critical pages (`src/pages/jobs`, `src/pages/auth`)
- Add a `test` script when introduced; include coverage for PRs touching business logic

## Commit & Pull Request Guidelines
- Commits: concise, imperative subject (e.g., "Add job import script"); group related changes
- Conventional Commits encouraged (e.g., `feat:`, `fix:`, `chore:`) but not required
- PRs must include: clear description, linked issues, verification steps, and UI screenshots when applicable
- Pre‑merge checklist: `npm run lint`, `npm run typecheck`, `npm run build` all pass; no changes in `dist/`
